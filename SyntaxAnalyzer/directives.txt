Grammar

The grammar of the alpha language is provided below. The symbols * and | have the same meaning as in regular expressions, while content enclosed in [ and ] denotes that it is optional (caution: do not confuse these with the literal tokens [ and ]).

program → stmt*

stmt → expr ;
             ∣ ifstmt
             ∣ whilestmt
             ∣ forstmt
             ∣ returnstmt
             ∣ break ;
             ∣ continue ;
             ∣ block
             ∣ funcdef
             ∣ ;

expr → assignexpr
             ∣ expr op expr
             ∣ term

op → + | - | * | / | % | > | >= | < | <= | == | != | and | or

term → ( expr )
             ∣ - expr
             ∣ not expr

| ++lvalue
| lvalue++
| --lvalue
| lvalue--
| primary

assignexpr → lvalue = expr

primary → lvalue
             ∣ call
             ∣ objectdef
             ∣ ( funcdef )
             ∣ const

lvalue → id
             ∣ local id
             ∣ :: id (Global scope access)
             ∣ member

member → lvalue . id
             ∣ lvalue [ expr ]
             ∣ call . id
             ∣ call [ expr ]

call → call ( elist )

             ∣ ( funcdef ) ( elist )

callsuffix → normcall ∣ methodcall

normcall → ( elist )

methodcall → .. id ( elist ) // equivalent to lvalue.id(lvalue, elist)

elist → [ expr [, expr]* ]

objectdef → [ [elist | indexed] ]

indexed → [ indexedelem [, indexedelem]* ]

indexedelem → { expr : expr }

block → { [stmt*] }

const → number | string | nil | true | false

returnstmt → return [ expr ] ;



1. Precedence and Associativity Rules
Precedence (High to Low)	Operators
1	(), [] (Function call, Array/Object access)
2	. , .. (Member access, Method call)
3	not, ++, --, - (Unary operators)
4	*, /, % (Multiplicative)
5	+, - (Additive)
6	>, >=, <, <= (Relational)
7	==, != (Equality)
8	and (Logical AND)
9	or (Logical OR)
10	= (Assignment)

Associativity:

    None: >, >=, <, <=, ==, != (These cannot be chained like a < b < c).

    Right: not, ++, --, -, =

    Left: All other operators.

2. Library Functions

The following are predefined as "library function" types in the global scope. They cannot be shadowed or redefined by the user.

    print, input

    objectmemberkeys, objecttotalmembers, objectcopy

    totalarguments, argument, typeof

    strtonum, sqrt, cos, sin

3. Scope Spaces and Visibility

    Unified Namespace: Library functions, user functions, variables, and formal arguments all share the same namespace. Naming collisions will occur if they overlap in the same scope.

    No Shadowing of Library Functions: You cannot define a variable or function with the same name as a library function.

    Function Names as R-values: User-defined function names are constants; they cannot be used as l-values (assigned to).

    Scope Levels: * Scope 0 (Global): Outside of any block or function.

        Nesting: Entering a block or function definition (starting at the formal arguments' parentheses) increases scope by +1.

        Note: A function's body block does not increase the scope again; it remains at the level of the formal arguments.

    Deactivation: When exiting a scope, symbols are not deleted but "hidden" (marked as inactive).

4. Symbol Access Rules (The "Alpha" Logic)

A function has access only to:

    Its own local variables and formal arguments.

    Global variables (only those at Scope 0).

    Any other functions currently in an active scope.

    Crucial Rule: A nested function cannot access the local variables or formal arguments of its parent (enclosing) function. It only sees its own locals and the globals.

5. Identifier Resolution Rules

When an id is used:

    Same Scope: If an active identifier A exists in the current scope, use it.

        Constraint: You cannot redefine a variable as a function or vice versa in the same scope.

    Enclosing Scope: If not in the current scope, look in outer scopes where access is legally permitted (following the rule above).

    Creation: If not found, a new identifier A is created in the current scope.

Specific Modifiers:

    ::id (Global): Forces a search only in Scope 0. If not found, it is an error.

    local id: Forces the search/creation only in the current scope. It prevents looking at outer scopes but will fail if it name-clashes with a library function.

6. Symbol Table Categories

For code generation purposes, you must store these three categories in your Symbol Table:

    Global: (Scope 0)

    Formal Arguments: (Function parameters)

    Local Variables: (Scope > 0, excluding formal arguments)

2) Symbol Table Lookup

To resolve a symbol encountered within a function, the search process follows these specific stages (stopping as soon as the symbol is found):

Step 1: Local Scope Search
Search within the local variables of the current scope (regardless of their specific type).

Step 2: Formal Arguments Search
Search within the formal arguments (parameters) of the current function.

Step 3: Intermediate Scopes Search
Search through all intermediate scopes (where 0<scope<current scope).

    Crucial constraint: In these intermediate levels, the search is restricted only to functions defined there. As per your earlier rules, local variables from outer functions are not accessible to a nested function.

Step 4: Global Scope Search
Search the global scope (Scope 0) for all symbols of any type (variables, user functions, or library functions).
If all the above steps fail:

The symbol does not exist → it must be inserted.

Special Case: ::symbol

If a symbol is preceded by the :: token:

    Search Constraint: The lookup is strictly performed in the global scope (Scope 0).

    Outcome: If the symbol is not found in the global scope, it results in a compile-time error (e.g., "global symbol not found").
